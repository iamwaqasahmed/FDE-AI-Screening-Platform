# 05 — The personal lab

Open [personal.py](work/app/personal.py) and put it beside yours.

The shell cites every document and ignores the floor. That shell makes the individual check say the citation drops the version or the audience, the citation serves a staff document to a patient, and the metric read ignores its budget. The message does not print a doc id or a floor.

The filled file returns nothing when a patient asks for a staff document. A kept citation carries audience, document id, and version. `audience` stays on the returned citation. That is expected. `meets_budget` accepts a value that clears its floor. [personal.jsonl](sources/release/slices/personal.jsonl) has citation rows and metric rows. It has no keep field. Do not add one.

The suite, from this folder, prints a line that starts with `Ran 11 tests`, then a blank line, then `OK`. The same line `Ran 11 tests` appears when the suite fails. The line under it has to be `OK`. The six test files match the packet byte for byte. Do not add a comment to only one side. Do not edit a test. A traceback names a test file. The app file is the same name without `test_`.

The suite imports all six modules. Do not delete any of them. The eval check loads the repair, the second run, and the label cost. The rcp check loads the backlog and the stage gate. The individual check loads this file.

A suite that prints `OK` can still fail a page check. The suite does not read the pages, and it does not read the workflow.
