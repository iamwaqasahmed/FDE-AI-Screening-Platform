# 05 — Tradeoffs, recommendations, deletions, sources

## Recommendation

Ship Alternative A from document 03. Take the translator tests and the enduring-versus-transitional sentence from B. Take the change-record fields from C. Reject D.

A is the only alternative that makes a boring file the graded work. B teaches the seam and can still accept a short file. C teaches authorization and can still wipe yesterday. D teaches a vocabulary of gaps the student is allowed to delete the file out from under. The engagement fails in B, C, and D in different costumes: a confident translator, a signed change, or a sharp monitoring paragraph, each sitting on `return arrived`.

## Foundation and advanced, restated

**Foundation, graded:** queued Ain, refused live-slot fault, missed night, poison quarantine, idempotent file id, translator that hides the local code, failed notice does not confirm, change record with backout, smoke that includes one synthetic book, monitoring answer that names the gaps.

**Advanced, described and not required for the pass:** promoting the nightly apply to a standard change after one clean night; a ready-marker on a real directory; two-way translation that writes the next drop back to Ain in Ain's codes. Evans's "both directions" is named so the architect can see the return path. Building that return path is how the day overruns.

If product wants the current "advanced" label preserved for the queue itself, the label is doing harm. The queue is the safety behavior. It cannot sit in an optional file.

## Implementation risks

- A harder file lesson will raise the paste-trained pass rate's inverse: more real failures. That is the point. Facilitator chapter 08 has to teach the four arrivals, or the day will look broken rather than strict.
- Hidden clinic codes plus a translator test is easy to get wrong and leak the code into a miss string. Reuse `contains_canary` and the existing "do not echo gold" tests. Add a test that the new miss strings do not contain the code.
- Tightening Monitoring will fail every current solution paste. The solution copy and the student journey hashes move together. Do not patch one.
- The release test that forbids `nightly` inside `cr-ain.md` can stay. The student's `change.md` is the document allowed to name the file. Do not "fix" the card by stuffing the protocol into it and then losing the discovery beat.
- Citing ITIL in a student chapter without the paid guide in the instructor's hand will drift. The student-facing sentence should be the PeopleCert purpose line and the field list. The CAB paragraph stays on the facilitator page, flagged.
