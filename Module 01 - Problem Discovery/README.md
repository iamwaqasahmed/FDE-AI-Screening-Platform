# Module 01 — Problem discovery

Hartland Regional Health Authority is a simulation. The people and the counts are for practice. They are not a real health system, and they are not instructions for patient care.

You do not need a health background. The first note in this folder teaches the words the case uses. After that, the work is the same for everyone: read a vague request, then find the problem in the files.

Set aside about half a day. Read the notes in order. Write when a note tells you to stop. The debrief is the answer key. Reading it early skips the skill this module exists to teach.

Do not open `data/truth`, `data/eval`, or `problem_simulation/config.yaml`. Those are for grading and for generating the world. The client did not hand them to you.

## What you will produce

1. An ask log, written in [03 — The ask](03-the-ask.md), before you open the data files.
2. A problem brief, written in [06 — Write the brief](06-write-the-brief.md), after you have counted the files and before you open the debrief.

## Read in this order

| Step | Note | What you do |
|---|---|---|
| 1 | [Health language](01-health-language.md) | Learn the words. No case files yet. |
| 2 | [The discovery skill](02-discovery-skill.md) | Learn the moves you will reuse on every client. |
| 3 | [The ask](03-the-ask.md) | Read one email. Stop and write the ask log. |
| 4 | [What people said](04-what-people-said.md) | Read the interviews. |

| 7 | [Debrief](07-debrief.md) | Compare your brief with the key. |

The skill list this module trains is in [FDE.md](../FDE.md): problem discovery, product judgment, domain learning, and working while the picture is still incomplete. The case folder is explained in [problem_simulation/README.md](../problem_simulation/README.md).
