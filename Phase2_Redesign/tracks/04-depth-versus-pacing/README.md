# Depth versus pacing

Proposal only. This folder does not edit lessons, checks, solution copies, or anything under `Idea_*`.

Phase 1 instructional research (`Idea_CrossCutting/06-instructional-design`) fixed a core path at one decision per lesson and at most one code completion in one file. Subsystems are optional extensions. No timetable is set. The redesign brief asks for principal-level forward-deployed engineering: investigate a messy enterprise, implement locally, and operate on AWS. Those two goals pull the same twenty lessons in opposite directions.

This track argues both sides from pages opened for this note, then sets a gate structure between "paste one function" and "build a platform company."

## Recommendation

A strong member of this mixed cohort, working alone, can finish **9 to 12 blocking mastery gates**. The center of that range is **10**. Offer **6 to 9 distinction labs**. The center is **7**.

Ten gates are three written decisions and seven running checks. Each running check is one behavior. The live AWS account is a distinction lab. The mastery cloud gate is a template plus a local policy check, and the allowed claim stops at "a pipeline can reject this control."

If the course bloats, cut the second environment first. A lesson that grows a full local build and a full AWS build loses the AWS build. The single cloud-policy gate stays. Duplicate labs and any blocking gate past 12 go next. The refusal, the one local behavior that makes it executable, and the rule that a skipped lab cannot be claimed in the capstone stay.

The range is a design judgment about this cohort and these sources. It is not a completion study.
