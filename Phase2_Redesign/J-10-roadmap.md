# J — How to build this, without building it in this phase

Nothing in this folder is implemented. The existing lessons stay as they are until a later project chooses a gate and writes it.

## Order

The simulator and the first four gates come before any AWS template. A student path that starts at module 7 has nothing to bound.

1. **Event log, gold graph, and three projections.** Cluster referral, Desk channel, Partner eligibility. One fault: the letter books. Checker for gate 3 only. This proves inheritance.
2. **Claims table and interview scripts** that do not contain the memo. Gates 1, 2, and 4. Delete nothing from the old course while this is tried beside it.
3. **Workflow, outbox, capability, file drop.** Gates 5–8. Reuse the fixtures Phase 1 already proved (Friday, Ain, letter-as-data). Rewrite the checkers that treat a missing file as a pass.
4. **Session, cross-patient denial, mart contract, channel.** Gates 9–12.
5. **Identity, customization decision, citation, evaluation.** Gates 13–16. The judge’s input must not include `pass`.
6. **Guard, deletion, incident, one repair, requirements.** Gates 17–20.
7. **Promotion, budget, serving simulator, drill.** Gates 21–24. Scenario knobs, not the old constants 149 and 252000.
8. **Templates and policy checks.** Gates 25–28. No live account in CI.
9. **Operate and hand over.** Gates 29–32.
10. **Extensions,** in the order students actually reach them: fusion, then a live apply.

## Staffing the build

Each gate is a small package: a projection or a fixture, a student file, a checker, a solution that appears after the check, and a chapter that does not contain the solution. One person can review a gate. A module is five of those, not one large document.

The AWS templates are one package owned by someone who will re-read the region list and the Bedrock model table at the time of writing. Those pages move.

## What to leave untouched

`Module 01` through `Module 04`, `problem_simulation`, `Idea_Module_*`, and `Idea_CrossCutting`. This folder is the proposal. A later implementation copies a gate into a new tree when the checker is ready. It does not edit a student chapter in place until that gate’s check exists.

## Done for this phase

The comparison, the blueprint, the local and AWS designs, the progression, the thirty-two gates, the backlog, the risks, the sources, and this order. Challenge tracks under `tracks/` may dissent. A dissent that beats the payload rule or the three-party case should be written into document H, not silently folded into the gates.
