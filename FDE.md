# Forward deployed engineer

In this course, a forward deployed engineer is the person who sits with a customer, turns a vague request into a small system the customer can run, and stops when the owner who must sign has not signed.

The customer here is Hartland Regional Health Authority, a simulation. The four parts below are the practice both tracks train. Who each track is for, and what you leave able to do, is [target_audience.md](target_audience.md). The program map is [README.md](README.md).

## 1. Production engineering

Enough to read a messy drop and keep a run inside the boundary the client already set.

- Read an extract that disagrees with its own cover note
- Follow the counting function instead of redoing the count in prose
- Start a service that writes an access log and a result file
- Leave images, the API key, and the answer key out of that run

## 2. Applied AI

Enough to keep a model in a bounded job and to measure that job.

- Put counts in tools and rules in retrieval
- Keep a draft from being relabeled as the rule in force
- Store the tool's dictionary as the result, including when the model invents a different sentence
- Refuse a retina grade, an unsigned referral, and a draft treated as current policy
- Score a labeled set and give a failure one name

## 3. Customer consulting

Enough to turn one platform request into a slice two readers can share.

- Write the ask in their words before improving it
- Separate the sponsor's goal from the operator's pain
- Learn the service's vocabulary from [Health language](health_language.md) and from the files
- Say the same slice once for the Chief Digital Officer and once for the ophthalmology lead
- Answer a new ask with a refusal or a later slice

## 4. Ownership in the client environment

Enough to leave something operable, and to leave it stopped when the signature is missing.

- Name who can be called about the run
- Hand off a start command, a log path, and a list of what the service will not do
- Keep the pilot stopped while `clinical_safety_owner` is unassigned

## What Week 00 leaves out

SQL, a second language, HTTP APIs, cloud infrastructure, container orchestration, continuous delivery, vector search, workshop design, and agile delivery planning sit outside the four-day case. Week 00 finishes without them.

Weeks 1 to 6 stay on this same client and go deeper into the service, the data, and the handoff. The guide is [Week 01 — Week 06](<Week 01 - Week 06/README.md>).
