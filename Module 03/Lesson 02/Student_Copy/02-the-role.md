# 02 — The role

[Chapter 00](00-background.md) said which release this is. This chapter is how you behave on the client's site for this release. Nothing is filed yet.

A forward deployed engineer works on the client's problem, inside the client's constraints, and leaves something the client can run and check. On this engagement the client is the Al-Waha Health Cluster. You are with the patient-access service. You hold all five parts yourself.

## The five parts today

| Part | What you will leave |
| --- | --- |
| Lead | The sprint: baseline, then adapter, then register, then memo, with the cloud fine-tune closed |
| AI or data engineer | The registered adapter, and the rank fit, the domain lines, and the preference edit |
| Application engineer | A weak local prompt that is not served, a letter relabel, a message intent, a router that refuses a bad call, and a local price |
| Product manager | The approach memo, with the Module 1 families kept and the customization table filled |
| Architect | Residency: four phi fields in the private zone, and clinic hours public |

You do these in [chapter 05](05-the-sprint.md), [chapter 06](06-the-baseline.md), [chapter 07](07-the-adapter.md), [chapter 08](08-the-advanced.md), and [chapter 09](09-the-pages.md), in that order. [Chapter 10](10-finish.md) files the two answers and runs the two checks.

There is no interview today. The checks do not read an interview note. You do not run an interview command, and you do not write interview notes.

## Where today sits

[Chapter 00](00-background.md) names this release. New files arrive on a schedule. You work from this folder. The grader's copy of the same pages is built in chapter 01. You read the copies in `packet/`.

The ruling is signed. Patient data still stays off `ext-large`. Training stays on the private cloud. A cloud fine-tune is closed.

A watermarked file copied into `work/` fails the check. The message does not print the watermark. Do not copy a file that carries the mark into `work/`.

The packet copies of `prompt.py`, `extract.py`, `intent.py`, `adapter.py`, `route.py`, `cost.py`, `qlora.py`, `domain.py`, and `prefs.py` stay the shells. You replace only the work copies. You do not delete `qlora.py`, `domain.py`, or `prefs.py`. The two checks do not require them. The suite does. `slice-lora` does not read them. Replace them after the finish checks are green. The tests are copied and not replaced.

This page is done when you can name the five parts and you have not copied a watermarked file into `work/`.
