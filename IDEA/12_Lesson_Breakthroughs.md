# 12 — Breakthroughs

The lesson text after a prediction uses a different object from the graded row. This catalog uses the real objects so builders share one picture. Do not paste these paragraphs into the student chapter above the exercise.

## INV-01

The warehouse is right about the receipt clock and wrong about the patient. Cleaning nulls or recomputing the mart passes the demo. The insight is that a metric needs a named start event. A binding that always throws the warehouse away fails when the label really is the hospital series. Afterward the student can take a new “cycle time” and ask which event starts it.

## INV-02

The sponsor’s sentence is a request to collapse three decisions. Classifying the letter looks like delivery. The insight is that a disclaimer does not create an owner. Afterward the student can refuse a feature and still ship the routing rule.

## INV-03

The tool call typechecks. The approval id is real and came from the letter. The insight is that the reader and the writer are different authorities, and the check belongs inside the tool. A workflow callback later is the same shape: resuming is not authorizing. Afterward the student looks for the origin of an identifier before trusting a valid payload.

## INV-04

The row committed and the patient got two messages, or a message for a dead visit. A transaction around the send, or a FIFO queue, passes a happy path. The insight is that exactly-once is a business key stored with the operation, because the record and the side effect are different systems, and a file can carry the same cancel as a queue. Afterward the student puts the key on the operation, not on the brand of the queue.

## INV-05

## INV-06

The insight is that a scorer who can see the label measures the label channel, and a decision rule has to be written before the counts. Afterward the student asks what the scorer was allowed to see.

## INV-07

## INV-08

A match of regions is not permission. A Gulf region is not the Kingdom. `sa-east-1` is São Paulo. A quotation fails the class rule for the same reason a letter does. Afterward the student classifies the object before choosing a service.
