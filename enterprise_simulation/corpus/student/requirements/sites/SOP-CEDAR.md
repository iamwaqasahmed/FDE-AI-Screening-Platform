# Cedar Ridge nightly file

Northline Access Collaborative
Cedar Ridge, rural Washington
Time zone of the file: America/Los_Angeles
Issue date: 1 February 2026
Author: Sam Nguyen, night file clerk
Procedure owner: Sam Nguyen

## What this issue is

This issue is the nightly file procedure for Cedar Ridge. Sam Nguyen wrote it on 1 February 2026 and follows it when he closes the night. Cedar Ridge is a rural clinic in Washington. The release this clinic makes is a file. The file has a header, a body, and a trailer. It leaves the clinic at a fixed civil time. It leaves on weeknights and it leaves on weekend nights. The Vancouver desk of Northline Access Collaborative keeps an office week of Monday through Friday. That office week belongs to the desk. It is not the calendar of this file.

Cascade Seattle keeps records. Jordan Hale may archive a copy of the trailer page after the file has left. Jordan does not build the file, does not assign the file id, and does not rewrite the trailer count from Seattle. Inlet Medical is a separate Washington clinic on the date of this issue. Inlet rows are not placed in a Cedar Ridge file, and an Inlet file id is not used as a Cedar Ridge file id. Fraser Burnaby is not the pattern for this night. Harper Singh is the integration engineer. Sam calls Harper only when someone asks again for a live booking path. The answer on that call remains the answer in the next section.

## No slot API

Cedar Ridge has no slot API. There is no call a desk can make that holds a chair at this clinic while a member is still on the phone. There is no method that turns a sentence spoken in Vancouver into a booking at Cedar Ridge. Sam Nguyen does not book a visit during a call. He does not ask Harper Singh to add a slot API. He does not borrow a live path from Cascade Seattle, from Fraser Burnaby, or from Inlet Medical.

When a clerk asks, during the day or during the night, whether a visit is booked, Sam answers from the file. If the visit is a detail row in a file he has already released, he says that it is in that file and he names the file id. If the visit is not yet a detail row in a released file, he says that it is not in a released file. He does not create a row in order to make a spoken sentence true. He does not leave a placeholder row for a call that is still in progress. A request that arrives after he has started the trailer is not squeezed in by a side message. It waits for the body of a file he is still allowed to change, or it waits for a later night, under the rules below.

Noel Park, June Lau, and Morgan Ibarra may ask from the Vancouver desk. Dana Okonkwo may ask as operations director. The answer does not change with the asker. There is no slot API. The file is the release.

## When the file goes

The file goes at 21:00 in America/Los_Angeles. That is the civil time Sam uses at the clinic. He starts the release when that clock at the clinic reads 21:00. He does not wait for the Vancouver counter to be open. He does not move the release to the opening of the next office morning. He does not pick a different hour because a stamp he was shown was written without a zone name.

Saturday is a file night. Sunday is a file night. The file goes at 21:00 in America/Los_Angeles on those nights by the same rule as on Monday, Tuesday, Wednesday, Thursday, and Friday. A weekend file is still a Cedar Ridge file. It is not relabeled as a Vancouver office day. The desk's office week remains Monday through Friday. Counting a Saturday file or a Sunday file as an office day of that desk is not a step in this procedure. Sam releases the file anyway.

If 21:00 arrives and the body is not ready, Sam does not send a partial body and promise the rest by telephone. He finishes the body, or he sends the body he is willing to stand behind, and only then writes the trailer. The release time remains 21:00 in America/Los_Angeles. A file that cannot be made ready by that time is not given a slot API in its place. It is finished late only when Sam writes both the late fact and the real send time on the night sheet. He does not backdate the sheet to 21:00 if the file left later. He does not invent an earlier send to match a sentence someone spoke in the afternoon.

## Header, body, and trailer

Sam writes the header first. The header carries the file id, the clinic name Cedar Ridge, and the civil time 21:00 America/Los_Angeles for the night he is closing. The file id is one string. He assigns it for that send. He writes it before he writes the detail rows. He copies the same string into the trailer before he releases the file. If the header string and the trailer string differ, he stops and makes them the same string. He does not release one body under two names.

The body is the list of detail rows. Each detail row is a visit he is releasing in this file. A row that is not in the body is not in the release. A conversation, a desk note, or a message from Morgan Ibarra is not a detail row until Sam writes it as one. He does not copy a Vancouver session id into the body and call that id a file id. He does not copy an Inlet Medical row into the body.

The trailer is the last record in the file. Sam writes it after the body is the body he means to send. Rows added after the trailer are not part of the send. If he must add a row, he adds it in the body, he does the count in the next section again, and he writes the trailer again with the same file id.

## Trailer count versus body count

Two counts are written, and they are not the same field.

The body count is the number of detail rows Sam counts in the body. He counts them after the body is closed for that attempt. He marks the margin in tens, then counts the remainder, then writes the total on the night sheet beside the words body count. A body with no detail rows has a body count of zero. Sam has not needed an empty body. If he ever sends one, the body count is zero and the file is still that night's file. An empty body is not a reason to invent a slot API.

The trailer count is the integer Sam writes inside the trailer. It is his claimed count of the detail rows. He writes it after the body count is on the sheet. The trailer count is not a second inventory kept in Seattle. Jordan Hale does not replace it with a count made the next morning.

Before release, Sam places the two numbers side by side on the release line: body count, then trailer count. He reads them aloud once. The procedure for the release is the comparison.

When the two numbers are the same, he may release the file. The trailer page he sets aside for Jordan Hale is the trailer of that released file, and the night sheet shows the pair that matched.

When the two numbers are not the same, he does not release. He recounts the body from the first detail row to the last. He writes the new body count on the next line of the sheet, without erasing the earlier count. He rewrites the trailer count from the recount he is willing to send. He compares again. He does not mint a second file id to hide the mismatch. He does not release a file whose trailer count and body count still disagree. He does not ask the Vancouver desk to ignore one of the two numbers so the night can close.

If a file has already left the clinic and the morning sheet shows a body count and a trailer count that differ, Sam writes both numbers in a note to Jordan Hale. The note names the file id, the body count, and the trailer count. The note does not tell Jordan which of the two numbers to keep. The note does not tell a desk which of the two numbers to read to a member. Both numbers stay on the note because both were written.

## A repeated file id

A file id is a string Sam has assigned to a send. A repeated file id is that same string on a later send. The later send may be a second transmission on the same night or a transmission on a later night, including a Saturday night or a Sunday night. Sam recognizes a repeat by comparing the string in the header to the file ids already listed on his night sheets. A likeness that is not the same string is not a repeat. He does not treat a near spelling as the same id.

When the string has already been used, Sam still writes the send he is making. He opens a new line on the night sheet. The line records the file id, the civil time of that transmission, the body count of that transmission, and the trailer count of that transmission. Each transmission keeps its own pair of counts. He does not merge the two bodies into one paragraph on the sheet. He does not drop the earlier line off the sheet because a later line uses the same file id.

Sam Nguyen believes that a repeat replaces the prior file. His belief is that the later send stands where the earlier send stood, that the two sends are not added together as two bookings, and that the earlier file gives way to the later one. He has worked with that belief since he took the night desk. He may write the belief in the margin of the night sheet, under his own name, beside the repeated file id.

This issue records that belief. This issue does not confirm it. The steps above do not delete the earlier transmission, do not mark it void, and do not instruct a receiver to discard it. Jordan Hale is not told that the later file is the only file. The Vancouver desk is not told that the earlier file has been replaced. A reader who still has the earlier file has not been given a rule, in this issue, that the earlier file is gone. The margin sentence is Sam's belief. The night sheet keeps every transmission he logged.

The same belief, and the same refusal to confirm it, applies on a weekend night. A Saturday repeat is logged as a Saturday transmission. It is not dropped because the Vancouver office is closed, and it is not declared the survivor of the pair.

## The morning after

On the morning after a file night, Sam leaves the night sheet where the day staff of the clinic can see the file id, the body count, the trailer count, and any margin note about a repeated file id. He does not rewrite the sheet to match a question from the Vancouver desk. He does not hold a weekend file until Monday so that the sheet and the desk's office week agree. Cascade records may pick up the trailer page when that office is open. The clinic's send does not wait for that office.

Questions about this issue come to Sam Nguyen. A question about a slot API comes to the same answer Harper Singh already has. A question about which of two transmissions a screen should show is not answered here. This issue tells Sam how to build the file, when to release it, how to count the body, how to write the trailer count, and how to log a repeated file id. It leaves his belief about replacement in the margin, unconfirmed.
