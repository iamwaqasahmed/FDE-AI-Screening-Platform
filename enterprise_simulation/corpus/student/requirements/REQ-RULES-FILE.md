# Cedar Ridge nightly file rules

Northline Access Collaborative
Cedar Ridge, rural Washington
Time zone: America/Los_Angeles
Header date: 1 June 2025
Author: Sam Nguyen, night file clerk

## What this book is

I am Sam Nguyen, the night file clerk at Cedar Ridge. This book is the way I release the nightly file. I wrote it on 1 June 2025. I follow it when I close the night. Cedar Ridge is a rural clinic in Washington. The file I send is the clinic's release for that night. Cascade Seattle keeps records, and Jordan Hale archives a copy of my trailer page, but Jordan does not build this file and does not assign my file id. The Vancouver desk has its own office week. That office week is not the calendar I file on.

Harper Singh, integration engineer, walked the clinic machines with me before I closed this book. We were looking for a live way to hold a visit. There is not one at this clinic. The pages below are the substitute I actually run: one file, one file id, one trailer count, sent at night.

## No slot API

Cedar Ridge has no slot API. There is no endpoint a desk can call to hold a visit at this clinic. There is no method that reserves a chair while a clerk waits on the phone. I do not book a visit by a live call, and I do not ask Harper Singh to wire one. Fraser Burnaby is not the pattern for this clinic. Cascade Seattle is not the pattern for this clinic. Inlet Medical is a separate Washington clinic, and its files are not mine. I do not place Inlet rows under a Cedar Ridge file id, and I do not treat an Inlet file id as a Cedar Ridge send.

If a caller asks for a same-night opening, the answer is the nightly file. The visit is in the file I send, or it is not in yet. I do not create a booking by any other channel while the night is open. A clerk at the Vancouver desk cannot call this clinic and receive a slot. I tell Harper Singh the same thing any time the question returns: there is nothing to call.

## The file id

Each send has one file id. I write the file id in the header before I write the body. I copy that same file id into the trailer. The file id is the name of that send. It is one string. I assign it for the night I am closing. I do not borrow it from Inlet Medical, and I do not take it from a file Jordan Hale already archived for another night.

The body rows belong to that file id. When I speak about the send the next morning, I speak about that one id. The header and the trailer must carry the same string. If I notice they differ, I stop and make them the same string before I release the file. I do not release a body under two names.

## A repeated file id

I have had nights when the same file id is sent more than once. This is my belief, and it is the rule I apply when I close the night. A repeated file id is a replacement, not a second booking. I do not add the two sends together. I do not open a second visit because the id came back. The later send stands where the earlier send stood. I have worked this way since I took the night desk. Nobody at Cascade records has handed me a different rule, and I do not wait for one. When I see my own file id again, I treat the new send as taking the place of the earlier one.

## The trailer count

After the body, I write a trailer. The trailer count is my count of the detail rows in the body. I recount the body once before I close the night, and the trailer count is that recount. If the body has forty detail rows, the trailer count I write is forty. The count sits in the trailer so the receiver can see the number I claimed.

I do not release the file while the trailer count and the body disagree. I correct the trailer before I send. I do not paper over a mismatch by minting a second file id for the same body. One night's send keeps the file id I already wrote, with a trailer count that matches the rows I am actually releasing. Jordan Hale receives the trailer page for the archive after that match is true. Jordan stores the page. Jordan does not renumber the file id and does not replace my count with a count made in Seattle.

The trailer is the last record in the file. Rows added after the trailer are not part of the send. If I must add a row, I add it to the body, I recount, and I write the trailer again with the new trailer count and the same file id.

## Weekend nights

I send the nightly file on weekend nights. Saturday night and Sunday night are file nights at Cedar Ridge, as are the weeknights. The Vancouver desk's office week runs Monday through Friday. That calendar belongs to the desk. It does not close this clinic's file. A weekend night still gets a file id, a body, and a trailer count. I am on duty for those nights. I do not skip a Saturday night or a Sunday night because the Vancouver counter is shut.

A weekend file follows every other rule in this book. There is still no slot API on a Saturday. The file id is still one string, written in the header and copied to the trailer. The trailer count still matches the body before I release the file. My belief about a repeated file id is the same on a weekend night as it is on a weeknight: a repeated file id is a replacement, not a second booking.

The morning after a weekend night, the file is already the release. I do not hold it for the Vancouver office to open. Jordan Hale's archive copy can wait for Cascade records to be at their desk. The clinic's send does not wait. If I am closing a Sunday night, the file still leaves that night.

## What I do not put in the file

I do not put another clinic's rows in a Cedar Ridge file. Inlet Medical keeps its own sends. I do not put a Vancouver session id in the body as if it were a file id. I do not leave the trailer off because the night was short. A short night still has a header, a body, a file id, and a trailer count. An empty body, if I ever had one, would carry a trailer count of zero and would still be that night's file. I have not needed an empty send, and I would still refuse to invent a slot call in its place.

Questions about this book come to me. I am the night file clerk. Harper Singh is the person I call only when someone asks again for a slot API, and the answer remains that Cedar Ridge does not have one.
